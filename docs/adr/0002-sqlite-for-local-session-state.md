# Use SQLite for local Session state

Vidscribe v1 uses SQLite as the operational index for active Sessions while keeping media and generated artifacts on disk. Each completed Session Folder also contains an explicit `session.json` manifest with portable, folder-relative asset references and the structured completed Session state. This makes a completed Session exportable and recoverable when its folder moves to a different environment: the manifest can rehydrate the local SQLite index. SQLite still matches the single-user local application and avoids operating a database server; the persistence layer should use portable relational patterns so PostgreSQL remains a viable future migration if remote or multi-user access is introduced.
